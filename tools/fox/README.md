# Лисёнок — генератор анимаций

Второй персонаж компаньона. Все кадры рисуются кодом (вектор → animated WebP 128×128, 25 fps),
поэтому позы, цвета и тайминги правятся прямо в `generate.py`.

```bash
pip install pillow numpy
python3 tools/fox/generate.py                     # все эмоции → app/src/main/res/raw/fox_*.webp
python3 tools/fox/generate.py tap pet             # только выбранные
python3 tools/fox/generate.py --wave3             # только анимации волны 3
python3 tools/fox/generate.py --car               # только автомобильные анимации
python3 tools/fox/generate.py --wave4             # только анимации волны 4 (сердечко, музыка, поворот)
python3 tools/fox/generate.py --preview /tmp/out  # плюс fox_preview.png / fox_preview.gif
python3 tools/fox/generate.py --gallery-only      # пересобрать галерею tools/fox/gallery.html
python3 tools/fox/generate.py --size 256 --out /tmp/fox256 tease   # другое разрешение (для замеров)
python3 -m unittest discover -s tools/fox         # проверки генератора (test_generate.py)
```

Генерация детерминирована: повторный запуск даёт побайтно те же файлы. При записи каждого файла
генератор предупреждает, если силуэт касается края кадра (обрезанные уши, лапы, хвост).

**Галерея:** `tools/fox/gallery.html` — откройте в браузере из клона репозитория (телефон не нужен):
карточки играют WebP прямо из `res/raw`, по клику анимация открывается отдельно (повтор, листание,
фон светлый / тёмный / «шахматка» для проверки прозрачности). Фильтры: «Волна 4» (по умолчанию),
«Автомобиль», «Волна 3», «Все».

### Волна 4: сердечко, музыкальные номера, поворот

| Файл | Где играет | Что происходит |
|------|------------|----------------|
| `fox_heart_transform` | HEARTS (финал поглаживания, случайно), FAREWELL (скрытие) | закрывает глаза, обнимает себя лапками, силуэт перетекает в большое оранжево-розовое сердечко с мордочкой, оно бьётся, вокруг сердечки; затем раскрывается обратно (4,6 с) |
| `fox_dance_side` | MUSIC | поворачивается боком (≈72°), танцует в профиль: покачивается, переступает лапками, виляет хвостом; один раз оглядывается на пользователя; поворачивается обратно (5 с) |
| `fox_microphone` | MUSIC, редкая | достаёт микрофон, поёт в него (рот «а / о / э» по слогам), жмурится и покачивается, жест свободной лапой, убирает (5,2 с) |
| `fox_guitar` | MUSIC, редкая | появляется гитара, одна лапа на грифе (аккорды меняются), другая перебирает струны, кивает в такт, финальный аккорд с искорками, гитара исчезает (5,6 с) |
| `fox_tail_back` | CALM, сценка, **не в движении** | поднимается, поворачивается боком и спиной, виляет пушистым хвостом, выглядывает через плечо, доворачивается лицом и садится (5,6 с) |

**Поворот** (`yaw`, класс `Turn`) — не сжатие и не зеркало: у каждой детали фронтального рисунка есть
глубина z, и при повороте на угол φ она встаёт в x' = 64 + (x − 64)·cos φ + z·sin φ. Голова и тело —
эллипсоиды (видимая ширина зависит от угла), в профиль появляется мордочка-«нос», плоские детали (глаза,
щёчки, грудка) сужаются по углу к зрителю и исчезают за головой, дальний глаз и дальняя лапа уходят за
силуэт, появляются задние лапы. Со спины — затылок (тёмный «загривок»), спина, обратная сторона ушей
(без розового), хвост перед спиной со своим контуром. `head_yaw` поворачивает голову отдельно от тела
(взгляд через плечо). При `yaw = 0` код рисует побайтно то же, что раньше (проверено хешами кадров всех
старых анимаций и тестом `test_new_pose_fields_keep_the_front_view`).

**Сердечко** (`heart` 0…1, `draw_heart_body`) — морфинг силуэта: из точки на груди 180 лучей, на каждом
расстояние до контура лисёнка плавно переходит в расстояние до контура сердца, поэтому форма именно
перетекает, а не растворяется. Уши сближаются и уходят в «лопасти», хвост и лапы втягиваются, цвет
уходит от оранжевого к розовому, глаза, щёчки и носик остаются. Сердце готово на `HEART_MOMENT_MS`
(2000 мс) — в этот момент приложение даёт короткий тактильный отклик; константа совпадает с
`AnimationPools.HEART_MOMENT_MS` (проверяет `test_heart_moment_matches_the_app`).

Новые предметы: `mic` (микрофон, рукоять в лапе, шарик у рта — следует за наклоном головы) и `guitar`
(гриф, корпус с розеткой, струны, колки; лапы считаются через `prop_at()` — одна на грифе, другая у
розетки). Новые рты: `aa`, `ee` (пение); поля позы `feet_dy` (шаг), `tail_scale`, `k` у лапы (толщина).

### Автомобильный компаньон

| Файл | Где играет | Что происходит |
|------|------------|----------------|
| `fox_driving`    | CALM, AUTO, **только в движении** | держит руль на «без десяти два», спокойно подруливает, смотрит на дорогу |
| `fox_seatbelt`   | TRIP_PREPARE (переход в AUTO) | тянет ремень из-за плеча, передаёт в другую лапу, защёлкивает, хлопает по нему |
| `fox_navigator`  | TRIP_PREPARE; CALM на стоянке или при подготовке | разворачивает карту, крутит её, «?» → идея, показывает направление стрелкой |
| `fox_mechanic`   | CALM, стоянка, редкая | достаёт гаечный ключ, затягивает болт (ключ ходит вокруг болта вместе с лапой), «фух», крутит ключ |
| `fox_tire_check` | CALM, стоянка | подкатывается колесо, лисёнок наклоняется, дважды тычет в шину (она проминается), одобрительно кивает |
| `fox_refuel`     | CALM, стоянка | держит заправочный пистолет со шлангом, стрелка датчика ползёт от E к F, «щёлк» — полный |
| `fox_car_wash`   | CALM, стоянка, редкая | трёт губкой с пеной по кругу, летят пузыри, любуется блеском |
| `fox_arrival`    | ARRIVAL (конец долгой поездки) | два прыжка с клетчатым финишным флажком, искорки |
| `fox_pothole`    | **только предпросмотр** | подбрасывает на кочке: уши взлетают, круглые глаза, приземление с покачиванием, «фух» |
| `fox_parking`    | ARRIVAL; CALM на стоянке | оглядывается через плечо, выкручивает руль, пищит парктроник, стоп — знак «P» |

Все начинаются и заканчиваются в спокойной позе: предмет «выскакивает» с лёгким перелётом, пока лапа
поднимается, и исчезает, пока она опускается, поэтому переход к CALM без скачка.

**Реквизит** (`draw_prop()`, поле позы `props`) рисуется в координатах тела: наклоняется, сжимается и
подпрыгивает вместе с лисёнком, а лапа рисуется поверх рукояти — предмет зажат в лапе, а не наложен
картинкой. Позиции лап считаются из предмета: `wheel_grip()` — точка на ободе руля с учётом поворота
(лапы поворачиваются вместе с рулём), `prop_at()` — точка в собственных координатах предмета (края карты),
у ключа головка стоит на болте, а рукоять с лапой ходит по дуге вокруг него. Свой тонкий контур у
каждого предмета; `back=True` — за телом (шланг), `front=True` — перед лапой (губка), `ground=True` —
стоит на земле и не наклоняется с телом (колесо).

| Предмет | Поля |
|---|---|
| `wheel` — руль | `turn` (градусы; оранжевая метка сверху поворачивается) |
| `wrench` — гаечный ключ | `rot` — направление от рукояти к зеву |
| `map` — карта | `unfold` 0…1, `rot` |
| `tire` — колесо | `spin` (протектор и гайки вращаются), `squash` — промятие от тычка |
| `belt` — ремень | `a` — крепление у плеча, `e` — язычок (в лапе), `b`/`buckle` — замок |
| `nozzle` + `hose` — пистолет и шланг | `squeeze` — нажатый курок; шланг уходит за тело |
| `sponge` — губка | `foam` 0…1 — шапка пены |
| `flag` — финишный флажок | `wave` — фаза волны, `side` — в какую сторону полотнище |

Новые наклейки: `gauge` (датчик топлива, `level`), `bubble`, `arrow`, `psign` (знак парковки).
Старые анимации не меняются: без `props` код рисования тот же.

Правила выбора (`AnimationPools` + `AnimationDirector`), теги:

| Тег | Правило |
|---|---|
| `CAR` | только в профиле AUTO |
| `DRIVING` | только когда машина едет (включая короткую остановку на светофоре); единственный «дополнительный» вариант, который не ослабляется в движении |
| `PARKED_ONLY` | только при подтверждённой стоянке: свежий GPS показывает остановку дольше 60 с, и это не остановка посреди поездки |
| `PREPARING` | можно и во время подготовки к поездке, вес ×3 (navigator) |
| `MAINTENANCE` | ключ, колесо, заправка, мойка — не чаще одной такой сценки за 4 мин |

Плюс прежние правила: сценки (`SCENE`) не играют в движении и не чаще раза в 45 с, у каждой свой
`minGapMs` (3–8 мин), `BASE` сохраняет ≥ 55 % веса. Если машина тронулась во время сценки, она
прерывается (как бабочка в PR #18); TRIP_PREPARE и ARRIVAL при начале движения сразу завершаются.

**Поездка** (`state/TripTracker.kt`): `PARKED → PREPARING → DRIVING → ARRIVED`.

| Что | Как определяется |
|---|---|
| PREPARING | переход в AUTO (Bluetooth или вручную) — **не** начало движения; через 5 мин без поездки → PARKED |
| DRIVING | свежий GPS ≥ 15 км/ч |
| ARRIVED | ≥ 10 мин езды (время остановок не считается) и затем подтверждение стоянки: обычно — отключение Bluetooth машины после ≥ 10 с остановки по GPS; без Bluetooth — остановка ≥ 8 мин с GPS всё это время |
| светофор, переезд, пробка | остановка < 8 мин — поездка продолжается; сценки «для стоянки» посреди поездки тоже не играют |
| пропал GPS | отсчёт остановки начинается заново; без GPS событий поездки нет |
| что считается GPS | только **новая** фиксация (`DrivingData.fixSeq` растёт), не старше 10 с и точнее 50 м (`GpsFixGate`, одно правило для `StateMachine` и детектора торможения); события акселерометра и гироскопа повторяют прошлую скорость и никуда как скорость не идут |
| скрыть и снова показать лисёнка | не смена профиля: поездка, её время и данные GPS сохраняются (`resetInteraction()` вместо `setProfile()`) |
| короткая поездка | заканчивается PARKED, без празднования |

`pothole` в пулы не входит (`AnimationPools.PREVIEW_ONLY`): надёжного детектора кочек пока нет,
`BrakeDetector` не менялся.

`curl_up → sleep_curled → wake_curled` — небольшая последовательность: её запускает вариант
`curl_up` в пуле FALL_ASLEEP (поле `next` у `AnimationVariant`), отдельных состояний для неё нет.
Продолжение включается, только когда `curl_up` **доиграл до последнего кадра** (лисёнок
действительно лежит клубком):

| Что случилось | Что играет |
|---|---|
| сон клубком → касание / музыка / звонок | `wake_curled`, затем CALM / MUSIC / PHONE_CALL |
| музыка или звонок начались, пока лисёнок укладывается | `curl_up` доигрывает → `wake_curled` → MUSIC / PHONE_CALL |
| касание, пока `curl_up` ещё идёт | обычный `wake` (из лежачей позы он ещё не вышел) |
| торможение, резкий поворот, утреннее потягивание, смена профиля | своя реакция; последовательность сброшена |
| персонаж сменился на слайма во сне | у слайма нет файлов — его обычный WAKE |

Всё это проверяет `SleepSequenceIntegrationTest` (машина состояний + директор + имитация
`CharacterView`), включая трёхчасовую сессию со случайными прерываниями.

### Общие функции движения

Новые анимации собраны из переиспользуемых функций (их можно брать и для будущих):

- easing: `ease_in`, `ease_out`, `ease_in_out`, `ease_out_back` (лёгкий перелёт), `window()` —
  «появиться → держать → уйти», `keys()` — ключевые кадры для чисел и кортежей,
  `spline()` — плавная траектория (Catmull-Rom, полёт бабочки);
- `gaze()` — взгляд с саккадами: глаза стоят, затем быстро перескакивают к новой цели;
- `spring()` / `lag()` — затухающая пружина: инерция хвоста после прыжка, чиха или взмаха,
  запаздывание взгляда и головы за движущимся объектом;
- `hop()` — прыжок с подготовкой (присед), растяжением в полёте, приземлением и затухающим
  «пружинением»; уши отстают от тела. `hop_dy()` — его вертикаль для пружин;
- `blink_shut()` — моргание: `single`, `double`, `slow` (сонное), `half` (ленивое полу-моргание);
- `ear_flick()` — подёргивание уха с отскоком;
- `breathe()` — дыхание (вторичное движение тела).

Новые поля позы (по умолчанию выключены — старые анимации рисуются побайтно так же):

| Поле | Что делает |
|------|------------|
| `eye_l`, `eye_r` | вид отдельного глаза (подмигивание: `eye_l="happy"`) |
| `open_l`, `open_r` | открытость отдельного глаза |
| `cross` | глаза сходятся к носу |
| `ear_scale_l`, `ear_scale_r` | длина отдельного уха (плюс прежние `ear_l`/`ear_r` — поворот) |
| `nose_wrinkle` | сморщенный нос (складки над носом) |
| `tongue`, `tongue_dx` | высунутый язык |
| `body_sx`, `body_sy` | сжатие только тела, голова сохраняет форму (лёжа) |
| `tail_wrap`, `tail_style`, `tail_peek` | хвост перед телом: `face` — перед мордочкой, `curl` — вокруг лап до носа; хвост рисуется вторым слоем со своим контуром и плавно проявляется |

Новые виды глаз: `squeeze` (зажмурился «> <»); рта: `smile`; наклейка: `butterfly`
(`flap` — раскрытие крыльев, `rot`).

Какие файлы играет каждое состояние, задаётся пулами в
`app/src/main/java/com/damitrya/mimio/state/AnimationPool.kt` (`AnimationPools`), а выбирает
конкретный вариант `AnimationDirector` (см. ниже).
Новая анимация = функция позы здесь + строка в `EMOTIONS` (+ `WAVE3`/`USAGE` для галереи) + строка в пуле.

Где что менять:
- палитра — константы в начале файла (`ORANGE_TOP`, `CREAM`, …);
- форма персонажа — `draw_character()`, глаза/рот — `draw_eyes()` / `draw_mouth()`;
- анимация эмоции — одноимённая функция позы (`tap()`, `pet()`, …), длина — словарь `EMOTIONS`;
- поднятые лапы — поле позы `arm`: одна лапа (dict) или список из двух (`draw_arm()`);
- наклейки — `extras` (`draw_extra()`: note, heart, sparkle, bang, sweat, shock, zzz, question,
  anger, puff, whoosh, phone, battery, waves, drop).

Персонаж выбирается в настройках приложения («Внешний вид → Персонаж»). **Сейчас слайм скрыт**
(`SettingsRepository.SLIME_HIDDEN`): выбор персонажа не показывается, всегда играет лисёнок; файлы и
fallback-логика слайма остались. `CharacterView`
ищет файл `<персонаж>_<имя>` и, если его нет, берёт оригинальный файл слайма. Если у слайма
нет такого файла, вариант пропускается (idle, музыка, тап) или заменяется заглушкой из пула
(`fallback`, например `annoyed` → `blink`).

## Характер и выбор анимаций

### CharacterMood (`state/CharacterMood.kt`)

Три параметра 0–100: **энергия** (нейтрально 65), **привязанность** (50), **любопытство** (50).

- Меняются постепенно: событие сдвигает значение на несколько пунктов, и чем ближе к 100, тем
  меньше шаг. Касание +1,5 к привязанности, поглаживание +5, приветствие +1; начало поездки
  +8 к любопытству и +5 к энергии; включение музыки +4 к энергии.
- Со временем всё возвращается к нейтральному: привязанность (период полураспада 6 ч),
  любопытство (1 ч; в тихом бодрствовании оно понемногу растёт к 65). Энергия днём медленно
  тратится (8/ч, не ниже 20), во сне восстанавливается (40/ч).
- Никаких наказаний: долгое отсутствие только возвращает к нейтральному, не ниже.
- Хранится в отдельном файле SharedPreferences `mimio_mood` (`PrefsMoodStore`), запись не
  чаще раза в 5 минут и только при заметном изменении, плюс при скрытии оверлея и остановке
  сервиса. При следующем запуске значения дополнительно «отдыхают» за прошедшее время (8 ч).

### AnimationDirector (`state/AnimationDirector.kt`)

Выбирает файл для состояния поверх пулов `AnimationPools` (пулы и их `cooldown` сохранены):

| Фактор | Влияние |
|--------|---------|
| теги варианта (`AnimTag`) | `SLEEPY` ×2,6…×0,4 от низкой к высокой энергии; `ACTIVE` ×0,3…×1,6; `EXPLORE` ×0,4…×2,2 по любопытству; `FRIENDLY` ×0,5…×2,0 по привязанности и ×1,5 в течение 90 с после касания |
| движение автомобиля | `SCENE` и `ACTIVE` (бабочка, игра с хвостом, встряхивание, вращение в танце…) не играют; остальные «дополнительные» ×0,6. Короткая остановка (до 60 с, светофор) считается движением |
| повторы | ×0,35 за каждое появление среди последних 8 выборов |
| редкие | `minGapMs` у варианта (бабочка — 5 мин, сценки — 3 мин) и не чаще одной сценки в 45 с |
| спокойствие | `BASE`-варианты (дыхание, оглядывание) сохраняют не меньше 55 % веса пула |

Если автомобиль тронулся (подтверждённое движение по GPS), когда уже идёт сценка или активная
анимация, она прерывается: в CALM `CharacterView` за 120 мс плавно меняет её на спокойный вариант,
перерыв FIDGET во время музыки сразу возвращается к MUSIC. Реакции на пользователя и другие
состояния не трогаются; алгоритм определения движения не менялся.

Директор только выбирает файлы и не меняет состояние, поэтому не может прервать ALERT, PET или
другие реакции. Пока идёт сценка (не-`BASE` вариант CALM, до 8 с), машина состояний откладывает
моргание и засыпание; реакции на пользователя и автомобиль приходят сразу. Случайность и часы
внедряются — выбор воспроизводим в тестах.

Слайм: новых файлов у него нет — варианты без `fallback` пропускаются; если у состояния вообще
нечего играть, `CharacterView` сразу завершает одноразовое состояние, а `StateMachine`
дополнительно завершает любое одноразовое состояние через 15 с, если конец не пришёл.

### Волна 4 в приложении

| Что | Правило |
|-----|---------|
| `heart_transform` после поглаживания | вариант пула HEARTS (вес 25 из 100, рядом `hearts` 60 и `proud` 15), не чаще раза в 2 мин и не два раза подряд; SHY по-прежнему после серии поглаживаний. Одно отпускание → одна реакция |
| прощание | «Скрыть» в уведомлении: состояние FAREWELL играет `heart_transform`, затем оверлей скрывается — по концу анимации или через `FAREWELL_TIMEOUT_MS` = 6 с. Повторное «Скрыть» — сразу. «Показать» во время прощания — лисёнок остаётся. Во время ALERT / резкого поворота и во сне — скрытие без анимации; торможение или смена профиля во время прощания — скрытие сразу |
| остановка | «Остановить» (уведомление, плитка, настройки) — сразу, без прощания: остановку не задерживаем ради эффекта. При системном уничтожении процесса прощания нет (код не вызывается) |
| `dance_side` | MUSIC, вес 10, `ACTIVE` (не в движении), не чаще раза в минуту |
| `microphone`, `guitar` | MUSIC, вес 4, `SCENE`: не в движении, не чаще раза в 4 мин каждая и 45 с между любыми сценками; обычные танцы остаются > 75 % времени. Пока идёт номер, перерыв FIDGET ждёт его конца; машина тронулась — номер сменяется обычным танцем |
| `tail_back` | CALM, вес 3, `SCENE`: не в движении (в том числе на коротком светофоре), не чаще раза в 5 мин; тронулись во время сценки — она прерывается |
| слайм | новых файлов нет: варианты пропускаются, FAREWELL у слайма играет `pet` |
| поглаживание → перетаскивание | если после распознанного удержания палец начал двигать персонажа, PET отменяется сразу и без финала HEARTS / SHY и не идёт в серию для SHY (`PressGesture`, `onLongPressCancelled`); так же при отмене жеста системой |

**Тактильная отдача** (`overlay/TouchHaptics`): лёгкий щелчок на касание (`KEYBOARD_TAP`), мягкий отклик
при распознавании долгого нажатия (`LONG_PRESS`), очень короткий тик в момент, когда лисёнок стал
сердечком (`CLOCK_TICK`). Только стандартный `View.performHapticFeedback` — он учитывает системную
настройку «Виброотклик», разрешение `VIBRATE` не нужно и не добавлялось. Не чаще одного тика на
распознанное действие и не чаще раза в 120 мс; на автоматические реакции (торможение, повороты, GPS)
не вызывается. Переключатель «Тактильная отдача» в «Поведении», по умолчанию включён.

### Память — как проверить на устройстве

Размер WebP в APK ≠ расход памяти. `CharacterView` держит LRU-кэш из 12 декодированных
`AnimatedImageDrawable`. Оценка (не измерена): каждый держит декодер и буферы кадра
(128² × 4 Б = 64 KB на кадр, обычно 1–2 буфера), то есть порядка 1–2 MB на весь кэш плюс
закодированные данные файла, если система держит их в памяти, а не отображает из APK
(до ≈0,7 MB на файл; худший случай для 12 файлов ≈6–8 MB). Вытесненные из кэша drawable
освобождаются сборщиком мусора вместе с нативной памятью.

Проверка за 30–60 минут:

1. Debug-сборка, выбран лисёнок, оверлей показан.
2. `tools/memcheck/memcheck.sh 60 30` — каждые 30 с пишет в `memcheck.csv` Java heap, Native heap,
   Graphics и TOTAL PSS, а в `memcheck.log` — строки приложения `MimioMem` (раз в минуту:
   заполненность кэша, число декодирований, кучи).
3. Пока идёт замер, время от времени касаться и гладить лисёнка, включать музыку: анимации и так
   меняются каждые 2–5 с, за час это ≈1000 переключений.
4. Норма: после первых минут значения выходят на плато; рост Native Heap / TOTAL PSS без конца —
   признак утечки. `decodes` растёт (кэш вытесняет старые файлы), `cached` не превышает 12.

## Разрешение 128 / 192 / 256 — замеры

Генератор умеет любое разрешение (`--size`): геометрия задана в координатах 128×128, а
суперсэмплинг растёт вместе с размером, поэтому пропорции и толщина контура сохраняются
(`test_other_resolutions_keep_proportions`). Замер на трёх файлах (WebP q90, 25 fps):

| Файл | 128 px | 192 px | 256 px |
|------|-------:|-------:|-------:|
| `fox_idle_small` (60 кадров) | 320 KB | 477 KB | 647 KB |
| `fox_tease` (60) | 326 KB | 484 KB | 653 KB |
| `fox_butterfly` (125) | 716 KB | 1075 KB | 1458 KB |
| коэффициент | ×1 | ≈×1,47 | ≈×2,0 |

- **APK:** все `res/raw/*.webp` сейчас ≈17,7 MB (лисёнок ≈15 MB, из них волна 3 ≈5 MB).
  Перевод всех файлов лисёнка на 256 px добавит ≈15 MB, на 192 px — ≈7 MB.
- **Память:** `AnimatedImageDrawable` декодирует кадры на лету, держа буфер кадра:
  128² × 4 Б = 64 KB, 192² — 144 KB, 256² — 256 KB на анимацию; при кэше из 12 drawable
  (`CharacterView.MAX_CACHED_DRAWABLES`) это ≈0,8 / 1,7 / 3 MB плюс служебные буферы декодера.
- **Плавность:** декодирование 256 px примерно в 4 раза дороже по пикселям, чем 128 px; на 25 fps
  это обычно в пределах возможностей, но проверить можно только на устройстве (здесь не проверено).
- **Зачем:** оверлей по умолчанию 150 dp, т. е. ≈450 px на xxhdpi — кадр 128 px растягивается в
  ≈3,5 раза. Разумный компромисс — 192 px.

Решение: разрешение **не меняли** (все файлы остаются 128×128). Если переходить — то целиком
для лисёнка и после замера FPS на реальном устройстве: `python3 tools/fox/generate.py --size 192`.
