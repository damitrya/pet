# Диагностика движения (профиль AUTO)

Встроенный регистратор, который показывает, почему лисёнок не реагирует на повороты, разгон и торможение.
Поведение персонажа он не меняет: пороги, приоритеты анимаций и логика поездки остаются прежними.

## Как пользоваться

1. Настройки → карточка «Диагностика движения» (видна, когда профиль не «только повседневный») → «Открыть диагностику».
2. Включить «Записывать диагностику». Новая запись удаляет предыдущий отчёт.
3. Запустить компаньона и ехать в профиле AUTO. Экран можно выключить: запись идёт, пока работает `CompanionService`.
4. Выключить переключатель — запись завершится, статистика и журнал сохранятся.
5. «Экспортировать отчёт» → TXT (UTF-8) через системное меню «Поделиться».
6. «Очистить данные диагностики» удаляет журнал, статистику и экспортированные файлы (только при выключенной записи).

## Как устроена запись

```
SensorDataProvider ──┬─ DrivingData ─► CompanionService ─► GpsFixGate.onVerdict ─┐
  (GPS, гироскоп,     │                    │                                     │
   акселерометр)      │                    └► StateMachine (решения, причины) ───┤
AccelerometerMonitor ─┴─ BrakeDetector (lastCheck / lastValue / calibration) ────┤
CharacterView (выбранный файл анимации) ─────────────────────────────────────────┤
                                                                                 ▼
                                  DrivingDiagnostics.sink = DrivingDiagnosticsRecorder
                                         │ (главный поток, только счётчики и агрегаты)
                                         ▼
                        DrivingDiagnostics.io (один фоновый поток)
                        files/driving_diagnostics/journal.txt + summary.properties
```

- Хуки в коде машины вызывают `DrivingDiagnostics.sink?.…`. Пока запись выключена, `sink == null` и ничего не происходит.
- Новых запросов GPS и новых слушателей датчиков нет: регистратор получает значения, которые код уже посчитал.
- Сырые показания датчиков не пишутся. Пишутся окна по 10 с (`SENSOR_STATS`) и «кандидаты» — эпизоды, где значение
  дошло хотя бы до 60 % порога детектора (`BRAKE_CANDIDATE`, `TURN_CANDIDATE`, `ACCEL_CANDIDATE`), с решением детектора
  и причиной.
- Каждое отклонённое GPS-измерение пишется; принятые — не чаще раза в 10 с (все считаются в статистике).
- Лимит журнала — 5 МБ. При достижении пишется `LIMIT_REACHED`, запись останавливается, переключатель выключается.
- Остановка сервиса ставит запись на паузу (`SESSION_PAUSED`); следующий запуск продолжает ту же запись.
- Координаты, маршруты и адреса не сохраняются: в `DrivingData` их нет.

## Причины отклонения

| Причина | Реальная проверка |
|---|---|
| `GPS_MISSING` | нет GPS (`hasGpsFix=false`) или в AUTO ещё не было пригодного измерения (`StateMachine.lastSpeedAt == 0`) |
| `GPS_STALE` | `GpsFixGate`: возраст > 10 с; `StateMachine`: последняя пригодная скорость старше 10 с |
| `LOCATION_INACCURATE` | `GpsFixGate`: погрешность > `MAX_ACCURACY_M` (50 м) |
| `SPEED_UNAVAILABLE` | `Location.hasSpeed()=false`. Код это не проверяет и принимает скорость 0, поэтому только `warning` |
| `SPEED_BELOW_THRESHOLD` | торможение: < 8 км/ч (`BrakeDetector.MIN_SPEED_KMH`); реакция на поворот: < 20 км/ч |
| `SENSOR_UNAVAILABLE` | датчика нет или `registerListener` вернул false |
| `CALIBRATION_PENDING` | ось не выучена: рывок ждёт подтверждения замедления по GPS |
| `ACCELERATION_BELOW_THRESHOLD` | значение не дошло до порога детектора |
| `DURATION_BELOW_THRESHOLD` | боковое ускорение выше порога, но меньше 300 мс |
| `COOLDOWN_ACTIVE` | ALERT 3 с, поворот 4 с |
| `STATE_BLOCKED` | состояние персонажа не позволяет реакцию (ALERT уже идёт, PET, не из `TURN_INTERRUPTIBLE`) |
| `ANIMATION_NOT_CONFIGURED` | на `DrivingData.isRapidAcceleration` нет реакции; нет файла анимации |
| `OVERLAY_HIDDEN` | состояние сменилось, но персонаж скрыт |

`DURATION_BELOW_THRESHOLD` и `OVERLAY_HIDDEN` добавлены к списку из задачи: без них пришлось бы подставлять неточные причины.
